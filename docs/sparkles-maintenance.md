# Managed filelock compatibility patch

**Keywords:** LiteLLM filelock 4 NIM proxy native wheel abi3 security compatibility archive source baseline

## LiteLLM source and dependency contract

The base is v1.109.1, `6c4ead4fc064d14e36b0c69d6795acc130c866bf` (upstream `stable/1.109.x` release, not an LTS line); the patches were first carried on v1.106.6 (`61c6ab78393ef45683dd7d963d2a315bd845e20b`, branch `sparkles-security-1.106.6`), rebased onto v1.108.2 (`831a14c8f48e189e24a85b47da1b31b44e0718b6`, branch `rebase-1.108.2`), onto v1.108.4 (`e6f080fb5633aa71ea81b652bd72069aff1f0228`, branch `rebase-1.108.4`) and then onto v1.109.1 on branch `rebase-1.109.1`. Upstream v1.109.1 still publishes filelock `>=3.16.1,<5` and Python `>=3.10, <3.16`; its 4.2.1 floor for Python 3.11+ is only a uv `constraint-dependencies` entry, which binds the repository lock and never reaches wheel metadata. The dependency patch therefore remains required. The dependency change follows upstream fix `dacaaad72ed25663ad7f40941c48f653a45289be`. Both package manifests accept filelock 4.2.4 through 4.x and Python 3.11 through 3.15 (the fork raises only the floor; the `<3.16` cap is upstream's). The repository's existing three-day dependency aging rule remains active; the lock selects filelock 4.2.10 while the workstation runtime may select a newer qualified 4.x patch. Upstream main removed the diskcache backend (#48114), so the LTS-only diskcache OSV ignore is gone. Public version remains the upstream base version (1.109.1), with the full fork Git SHA identifying the patch

## LiteLLM rebase procedure

Rebase onto a new upstream LTS tag on a new branch `rebase-<version>` created from that tag; leave the previous branch untouched for rollback. Add the tag to the clone's pinned fetch refspec so `/git-review` floors at the new base: `git config --add remote.origin.fetch +refs/tags/v<version>:refs/tags/v<version>`. Replay the fork commits and resolve manifest conflicts by reading both sides. Resolve lock conflicts by taking the upstream lock and rerunning `uv lock`; rerun `uv lock --upgrade-package filelock` when the upstream lock preference would move filelock below the previous fork lock. Drop a fork commit only when the new base already carries its change. Regenerate the type baseline as described below, run the focused cooldown tests and build the wheel from a clean `git archive` export of the branch HEAD, so uncommitted worktree changes never enter the artifact. Then update the base references in this document

## LiteLLM wheel build and verification

Build from clean committed source with `bash scripts/build-security-wheel.sh <new-artifacts>/wheels`. The wrapper sets a persistent Cargo cache, four build jobs and reduced scheduling priority; explicit caller overrides remain supported. The existing pinned Maturin backend emits an arm64 ABI3 wheel for all supported Python minors. Preserve the build log, source commit, wheel hash and installed package graph. The persistent target directory avoids repeating the first seventeen-minute native build

Import the installed native bridge on each supported Python minor, including filelock 4.2.4 at the minimum supported interpreter. Run the existing CLI settings and configure tests against the installed wheel. Scoped CLI qualification can stop conftest discovery at `tests/unit/proxy/client`; its one secret-vault fixture must come unchanged from the upstream proxy conftest and `FakeSecretVault` implementation. This avoids starting unrelated database integration fixtures. Record this qualification scope explicitly

## LiteLLM runtime cutover and rollback

Prepare a permanent candidate with the proxy extra and Pillow 13, then audit every installed package with zero omissions. Exercise the actual proxy on loopback with a local NIM-compatible provider: Chat Completions, Messages translation, and 429/5xx key failover. No real provider request or customer credential is needed

The owned consumer is control-plane `scripts/ensure-nim-proxy.sh`, which serves localhost port 8084. Preserve the old uv tool receipt and environment, verify active requests have drained, select the qualified candidate and restart only that daemon. Verify actual process executable, listener and both request surfaces. Failed startup or behavior requires restoring the old selection and restarting it. When upstream publishes a compatible release, qualify that wheel and replace the immutable fork pin through normal tool maintenance

## LiteLLM archive installation and local quality gates

Use a full-commit GitHub archive URL ending `.tar.gz` rather than fetching all Git history. Preserve the downloaded SHA256, compare every original archive file with the actual uv build-source directory, then compare installed Python modules with the independently qualified wheel. Ordinary uv 0.13.6 tool installation strips URL hashes and writes empty archive provenance; its URL fragment is not proof of byte verification. Never manufacture installer provenance

Keep the same persistent Cargo cache and four-job bound when uv invokes Maturin. Prepare a permanent candidate tool root with its three normal entry points before selecting it. Preserve the old receipt and environment; atomic selection must retain rollback. An inactive NIM daemon stays inactive after tool selection

The managed wildcard cooldown patch honors explicit deployment exception policies. Upstream v1.109 moved the cooldown handlers from the router instance to a `RoutingContext` (`ctx.settings()`), so the patched `provider_default_deployment_ids` check and its test now take the context. Multi-key NIM pools opt into immediate quarantine for rate limits, timeouts and server failures; single-key pools retain availability. Qualify each Chat Completions and Messages request with fresh proxy/provider state for each 429 and 503 case

The fleet type gate starts from the two touched files at the clean upstream base (v1.109.1 `6c4ead4fc064d14e36b0c69d6795acc130c866bf`; previously v1.108.4 `e6f080fb5633aa71ea81b652bd72069aff1f0228` and v1.108.2 `831a14c8f48e189e24a85b47da1b31b44e0718b6`; originally pre-patch commit `0d318e29a46996fd67176c3978a95d6e250f0fc6` on v1.106.6), checked with basedpyright 1.40.2. Regenerate it from the clean upstream files on every rebase, then check the patched files with `--baselinemode=discard`. Its initial committed baseline contains only those existing upstream diagnostics, never diagnostics from the cooldown patch. New diagnostics remain blocking. Use a local `.venv` pointing at a permanent wheel-based development environment with the proxy extra and required pytest plugins; otherwise the generic gate rebuilds the whole editable native project for focused tests

## LiteLLM registered tool directory and test isolation

The stable uv tool root must remain a real directory. `uv tool list` ignores symlinked tool roots and treats sibling backup directories as additional tool names. Before an atomic exchange of the old and candidate directories, relocate every candidate Python console-script shebang to the stable interpreter path. Keep rollback directories outside the uv tools root. A candidate-path alias may point back to the selected real directory after exchange. Verify `uv tool list --show-paths`, all three public entry points, actual imports, native bridge and full advisory coverage

When copying qualification tests out of the checkout, preserve their relevant local conftest chain. The CLI conftest provides both fake Codex version probes and isolated Claude/Codex homes plus a scratch statusline path. Omitting it produced missing fixtures and rewrote the generated statusline helper during a discarded run. The helper was verified byte-identical to the prior installed release template; the main configuration files were untouched. The corrected isolated run passes all 246 CLI tests against the actual candidate interpreter. The v1.108.4 qualification ran 1210 scoped tests (1032 CLI) and needs the pytest-asyncio, responses and requests-mock plugins in the candidate environment; without requests-mock, 33 tests error at setup. The v1.109.1 qualification ran 1388 scoped tests (1201 CLI) the same way, plus the focused cooldown file (204 tests) and the rest of `tests/unit/router_utils` against the wheel-based development environment; that copy also needs `tests/fake_openai_endpoint.py`, `tests/large_text.py`, `tests/_vcr_redis_persister.py` and `tests/unit/litellm_core_utils/event_loop_lag.py`, and `test_embedding_batch_size_check.py` needs `prometheus_client`, which the dev group omits. From v1.109 `litellm.rust_bridge` no longer exports `native_bridge_available`; the native import check imports `litellm.rust_bridge._native` and `litellm.rust_bridge.runtime` instead
